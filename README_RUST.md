# VOIDMAW - Rust 1.80 Version

## Description
This is a Rust 1.80 port of the original Voidmaw memory scanner bypass technique. This technique hides problematic code from antivirus vendors by masking executed instructions with INT3 breakpoints, revealing only one instruction at a time per thread.

This is an improved version of [Voidgate](https://github.com/vxCrypt0r/Voidgate), compatible with all C2 beacons, handling multithreaded payloads and executables generated by tools such as [pe_to_shellcode](https://github.com/hasherezade/pe_to_shellcode).

## Architecture

This technique consists of two programs:

### 1. Dismantle
Responsible for recording all uniquely executed instructions and their offsets. Creates a header file (or Rust module) for use with Voidmaw.

**Features:**
- Records executed instructions using PAGE_GUARD protection
- Uses Vectored Exception Handler (VEH) for instruction capture
- Encrypts recorded instructions with XOR
- Masks executed instructions with INT3 (0xCC)
- Generates output file with encrypted instruction map

### 2. Voidmaw
Responsible for executing the processed payload with instruction-level masking.

**Features:**
- Installs VEH for EXCEPTION_BREAKPOINT handling
- Decrypts and executes one instruction at a time
- Re-masks previous instructions with INT3
- Supports multithreaded payloads
- Preserves MZ header for reflective loaders

## Building

### Prerequisites
- Rust 1.80 or later
- Windows SDK (for Windows API bindings)
- Target: `x86_64-pc-windows-msvc` or `i686-pc-windows-msvc`

### Build Commands

```bash
# Build both projects
cargo build --release

# Build only Dismantle
cargo build --release -p dismantle

# Build only Voidmaw
cargo build --release -p voidmaw

# Build for 32-bit Windows (if on x64)
rustup target add i686-pc-windows-msvc
cargo build --release --target i686-pc-windows-msvc
```

The compiled binaries will be in:
- `target/release/dismantle.exe`
- `target/release/voidmaw.exe`

## Usage

### Step 1: Run Dismantle

```bash
dismantle.exe -p "C:\path\to\payload.bin" -o "./payload_out.h" -a "optional arguments"
```

**Arguments:**
- `-p, --payload <FILE>`: Path to the initial payload file
- `-o, --output <FILE>`: Path where the output header file will be saved
- `-a, --args <ARGS>`: (Optional) Arguments to pass to the payload

**Important Notes:**
- The payload must match the architecture (x64 Dismantle requires x64 payload)
- During recording, ensure the payload executes the code branches you want to capture
- Press "OK" in the message box to stop recording
- Run with appropriate permissions (e.g., as Administrator for mimikatz)

### Step 2: Convert Generated Header to Rust

The Dismantle tool generates a C++ header file. You need to convert it to Rust format and update `voidmaw/src/payload.rs`.

**Example conversion:**

C++ header output:
```cpp
unsigned char payload[] = {0xcc,0x48,0x89,...};
int payloadSize = sizeof(payload);
std::unordered_map<DWORD, std::vector<unsigned char>> payloadExecutedAsm;
std::vector<unsigned char> encryptionKey;
void InitMap() {
    encryptionKey.push_back('\x1a');
    // ...
    aux.clear();
    aux.push_back('\x48');
    aux.push_back('\x89');
    payloadExecutedAsm[0] = aux;
    // ...
}
```

Convert to Rust in `voidmaw/src/payload.rs`:
```rust
use indexmap::IndexMap;

pub static PAYLOAD: &[u8] = &[0xcc, 0x48, 0x89, /* ... */];

pub fn init_map() -> (IndexMap<u32, Vec<u8>>, Vec<u8>) {
    let mut payload_executed_asm = IndexMap::new();
    let mut encryption_key = Vec::new();

    // Initialize encryption key
    encryption_key.push(0x1a);
    // ...

    // Initialize map entries
    payload_executed_asm.insert(0, vec![0x48, 0x89]);
    // ...

    (payload_executed_asm, encryption_key)
}

pub fn get_payload_size() -> usize {
    PAYLOAD.len()
}
```

### Step 3: Rebuild and Run Voidmaw

```bash
# Rebuild with new payload
cargo build --release -p voidmaw

# Run the payload executor
voidmaw.exe
```

## Key Differences from C++ Version

### Improvements
1. **Memory Safety**: Rust's type system prevents many memory corruption bugs
2. **Modern Tooling**: Cargo build system and dependency management
3. **Cross-compilation**: Easy to target different Windows architectures
4. **No External Build Tools**: No need for Visual Studio or MSVC project files

### Limitations
1. **Command-line Argument Modification**: The PEB manipulation for changing process arguments is not implemented in the Rust version due to complexity. If your payload requires specific arguments, you'll need to modify the payload itself or extend the code.

2. **Generated Output Format**: Dismantle still generates C++ header files. You must manually convert them to Rust format (a conversion tool could be created).

## Technical Details

### Exception Handling Flow

**Dismantle (Recording Phase):**
1. Set PAGE_GUARD on payload memory
2. Create thread executing payload
3. VEH catches STATUS_GUARD_PAGE_VIOLATION (0x80000001)
4. Record instruction at exception address using iced-x86 decoder
5. Set TRAP_FLAG (EFlags |= 0x100) for single-step
6. VEH catches EXCEPTION_SINGLE_STEP
7. Restore PAGE_GUARD protection
8. Repeat until user stops recording

**Voidmaw (Execution Phase):**
1. Load masked payload (INT3 instructions)
2. Install VEH for EXCEPTION_BREAKPOINT (0xCC)
3. Create thread on masked payload
4. VEH catches INT3 exception
5. Lookup offset in map, decrypt instruction
6. Write decrypted bytes at exception address
7. Queue previous instruction for re-masking
8. Continue execution
9. Only one instruction visible per thread at any time

## Debugging

To debug the VEH in a debugger, you may need to change INT3 masking to a different opcode (e.g., 0x06 for EXCEPTION_ILLEGAL_INSTRUCTION on x64) since some debuggers don't allow handling EXCEPTION_BREAKPOINT.

Change `ASM_INT3` constant in:
- `dismantle/src/veh.rs`
- `voidmaw/src/veh.rs`
